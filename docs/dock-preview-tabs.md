# dsh-kit 右侧坞多文件预览标签 + 坞快捷控制（全部关闭 / 收起）

> 状态：**已实施，待用户 GUI 实测（2026-09-05）**。承接浏览器面板升级
> （`browser-panel-upgrade.md`）落下的右侧标签页容器，本轮把"预览"从单文件
> 升级为多文件二级标签，并给坞头加快捷控制。

## 用户定稿决策（2026-09-05）

- **二级标签**：右坞仍是预览/任务/浏览器三个大标签，预览大标签内套一排文件
  小标签（与浏览器面板页签条同款交互）；不用"每个文件占一个右坞大标签"的
  平铺方案（文件多时标签条拥挤）。
- **数量上限默认 8，设置卡可配 1-20**（VS Code 思路）：超过时打开新文件自动
  关掉**最久没看**的那个（LRU，绝不含本次刚打开的）；已存在的文件再次打开 =
  置顶激活，不逐出自身。
- **坞头两个快捷按钮**：全部关闭（清空三标签收容器）与最小化（暂时隐藏，
  右缘留竖条一键展开）。
- **最小化而非隐形收起（用户实测后修正定稿）**：首版"收起"只是置位标志、
  没有消费方（渲染门漏写），面板纹丝不动——真 bug；且用户语义是"最小化"：
  隐藏后右缘留一枚竖条（DockStub，竖排文字显示当前标签名，多文件预览带计数），
  点击即展开。存在性状态全保留，入口按钮同样可恢复；最小化视为人为退出
  （agent 导航不弹回）。

## 实施记录（2026-09-05）

### 数据模型（client kitUi）

- `openFile/openFrom/openUntracked` 单值 → **`previews: [{path, from,
  untracked, usedAt}]` + `activePreview`**；`usedAt` 在打开/激活时刷新，是 LRU
  的唯一依据。
- 新增 `dockCollapsed`（最小化）：存在性保留、右缘竖条（DockStub）与入口按钮
  均可恢复；**最小化视为人为退出**——置 autoOpen 抑制，agent 导航不再弹回
  （点浏览器入口/标签解除）。渲染门在 KitSurfaces：`dockAlive && !collapsed`
  才挂 RightDock，收起态挂 DockStub（首版漏写此门是"收起没成功"的根因）。
- 纯函数 `openPreviewTab`（开/置顶/激活/LRU 逐出）/ `closePreviewTab`（关单
  文件、激活位顺延邻居）/ `previewLimit`（读设置快照，未就绪回落 8），均在
  render-check 里有纯逻辑用例。

### 渲染与交互

- 预览大标签内：文件小标签条（**>1 个文件才显示**，单文件保持原简洁形态，
  chip = 文件名 + ×）+ 每文件一个 FileContentPane 实例（非激活 display:none
  保挂载——切回滚动位置/编辑草稿不丢；key=path）。
- 预览大标签标题在多文件时显示计数：`预览 (3)`。
- 坞头右侧两按钮：全部关闭（`previews/jobs/browser` 全清 + 收容器）、最小化
  （`»`，置 dockCollapsed；浏览器标签存在则同时置 autoOpen 抑制）。
- Esc 语义细化：预览大标签激活时 Esc 关**当前文件**（小标签级），非预览标签
  仍关整个大标签；收起态不吞 Esc。
- 入口按钮（任务/浏览器）在收起态点击 = 恢复（aria-pressed 在收起态熄灭）。
- 文件树改名/删除的 `closeStalePreview` 适配多标签：批量移除命中路径（含子
  路径），激活位被移除时顺延到剩余最后一个。

### 设置

- 宿主 schema `previewMaxTabs: z.number().step(1).min(1).max(20).default(8)`；
  设置卡挂在「文件树」组下（bool/number 字段渲染器支持 per-field max，
  `cfgParse` 的 number 上界从硬编码 8 改为读字段配置）。

## 已知边界

- 非激活文件若处于 diff 视图，其低频 diff 轮询在隐藏期间继续跑（沿用原
  diff-follow 设计，未按可见性门控）。
- 收起目前无独立快捷键，恢复走入口按钮（任务/浏览器/任意文件打开动作）。
